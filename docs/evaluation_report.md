## 1. アーキテクチャ

### 強み

- **明確な層構造**: API → Orchestrator → Agent → Tools の責務分離が適切
- **DAGベースのタスク管理**: `TaskGraph` がトポロジカルソート（Kahn's algorithm）で依存関係を正確に解決し、最大限の並列実行を実現
- **メッセージバス**: `MessageBus` によるエージェント間非同期通信で疎結合を維持
- **プロジェクト階層化**: Parent-Child関係による大規模プロジェクト分割が可能
- **ローカルLLM対応**: Ollama/vLLM両対応で、クラウド依存なしに動作

### 改善点

- **Orchestrator が 751行のモノリシック実装**: `run_async()` が約300行で認知的複雑性が高い。計画→分解→実行→レビューのフェーズ分離が不十分
- **キャッシング戦略の欠如**: LLM呼び出し結果をキャッシュしないため、同一プロンプトが反復される可能性
- **リソースリーク対策が限定的**: タスク状態がメモリ上のみ保持。長時間実行で蓄積リスク

## 3. セキュリティ

### 実装済み対策

| 対策 | 実装 | 詳細 |
|------|------|------|
| コマンドホワイトリスト | `ExecTools` | python/pytest/pip のみ許可 |
| ブロックリスト | `ExecTools` | rm/sudo/chmod/kill 等を拒否 |
| パストラバーサル防止 | `FileTools` | `path.relative_to(workspace)` で範囲外アクセス検出 |
| ワークスペース隔離 | `WorkspaceManager` | プロジェクトごとに独立ディレクトリ |
| サブプロセスサンドボックス | `ExecTools` | `shell=False`, `cwd` 制限, タイムアウト |
| 実行制限 | `AgentLimits` | max_iterations=10, timeout=300s |
| Project ID 検証 | API routes | 正規表現 `_SAFE_ID_RE` で安全性チェック |

### 未対応リスク

| リスク | 深刻度 | 詳細 |
|--------|--------|------|
| プロンプトインジェクション | 高 | ユーザー入力（goal, description）が直接プロンプトに埋め込まれる |
| WebSocket認証なし | 高 | 任意のproject_idで他プロジェクトの実行状態を監視可能 |
| API認証なし | 中 | 全エンドポイントが無認証でアクセス可能 |
| pip install 任意パッケージ | 中 | エージェントが任意のPyPIパッケージをインストール可能 |
| タイムアウト後のクリーンアップ不完全 | 低 | LLMプロセスがバックグラウンドで継続する可能性 |
